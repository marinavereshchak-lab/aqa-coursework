# План автоматизации для проекта AqaShop

## 1. Перечень автоматизируемых сценариев

1. Валидация полей формы.
2. Успешная покупка тура по дебетовой карте.
3. Попытка покупки тура по невалидной дебетовой карте.
4. Успешная покупка тура по кредитной карте.
5. Попытка покупки тура по невалидной кредитной карте.
6. Тестирование корректного отражения статуса заказа в БД.

---

## 2. Перечень используемых инструментов и обоснование выбора

- **Docker Compose** — тестовый стенд (база данных, приложение, эмулятор шлюза).
- **MySQL** — база данных проекта.
- **DBeaver** — ручная проверка и скриншоты.
- **mysql-connector-python** — прямое подключение к MySQL из теста.
- **Python** — язык написания автотестов.
- **Selenium WebDriver** — UI‑автоматизация (навигация, заполнение форм, проверка сообщений).
- **Allure** — формирование отчётов по результатам тестов.

---

## 3. Перечень и описание возможных рисков при автоматизации

- **Нестабильность эмулятора шлюза.**  
  Gate‑simulator может отвечать с задержками или возвращать ошибки при высокой нагрузке.
- **Проблемы с сетью Docker.**  
  Контейнеры могут подниматься с задержкой, и тесты начнут выполняться до готовности БД.
- **Изменение структуры БД (новые колонки, переименования).**  
  Если кто‑то изменит схему БД (например, переименует колонку `status` в `order_status`), все тесты начнут падать с ошибкой SQL.
- **Конфликт данных.** 
    Параллельный запуск тестов ломает данные в БД.
